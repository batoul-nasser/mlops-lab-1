Question 2
What is `--backend-store-uri` used for? What is `--default-artifact-root` used for? What is the difference between metadata and artifacts?

`--backend-store-uri sqlite:///mlflow.db` tells MLflow where to store the experiment metadata.

This includes information such as:
- experiments
- runs
- parameters
- metrics
- run status
- timestamps

`--default-artifact-root ./mlruns` tells MLflow where to store the files generated by the runs, such as trained models and other output files.

The difference is that metadata describes the run and its results, while artifacts are the actual files produced during the experiment.


Question 3
Why shouldn't `mlflow.db` and `mlruns/` be tracked by Git, and why shouldn't they be tracked by DVC either?

`mlflow.db` and `mlruns/` are generated locally when experiments are run. They are not source code and they can change frequently.

They should not be tracked by Git because Git is mainly used for versioning the code and configuration files.

They also do not need to be tracked by DVC because MLflow already manages experiment metadata and artifacts.

In this project, Git is used for the code, DVC is used for the datasets, and MLflow is used for tracking experiments and their outputs.

Question 5
What is the difference between mlflow.log_param and mlflow.log_metric? Why does log_metric take a step argument and log_param does not?

mlflow.log_param is used for values that are fixed for the whole training run.

Examples include:

learning rate
batch size
number of epochs
dataset
model architecture

mlflow.log_metric is used for values that are calculated during training.

Examples include:

training loss
validation loss
validation accuracy
test accuracy

A metric can change from one epoch to another, which is why log_metric can use a step argument.

For example, validation accuracy can be logged at epoch 1, epoch 2, epoch 3, and so on.

Parameters do not need a step because they stay the same during the whole run.
